1. Visión general

GastroHub Frontend es una Single Page Application (SPA) con soporte de Server-Side Rendering (SSR) construida con Angular 21. Se comunica con una API REST backend vía HTTP y gestiona la sesión del usuario mediante JWT (JSON Web Tokens).

La aplicación implementa un sistema de roles estricto con tres perfiles de usuario: ADMIN, MESERO y COCINA, cada uno con rutas y funcionalidades propias protegidas por guards.

4. Configuración de la aplicación

El archivo app.config.ts registra todos los providers globales usando la API funcional de Angular:

export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),   // Manejo global de errores JS
    provideRouter(routes),                   // Enrutamiento basado en routes[]
    provideHttpClient(
      withFetch(),                             // Usa fetch API (compatible SSR)
      withInterceptors([authInterceptor, errorInterceptor])
    ),
    provideClientHydration(withEventReplay()) // Hidratación SSR + replay de eventos
  ]
};
ℹ Los interceptores se registran en orden: primero authInterceptor adjunta el token, luego errorInterceptor procesa la respuesta.

6. Guards de acceso

authGuard

Verifica que exista un token JWT válido y no expirado. Si no, redirige a /login.

export const authGuard: CanActivateFn = () => {
  const authService = inject(AuthService);
  const router = inject(Router);

  if (authService.getToken() && !authService.isTokenExpired()) {
    return true;
  }
  router.navigate(['/login']);
  return false;
};

roleGuard

Fábrica de guard que recibe la lista de roles permitidos. Consulta el rol actual del usuario desde AuthService.userRole() (signal reactivo).

export const roleGuard = (allowedRoles: UserRole[]): CanActivateFn => {
  return () => {
    const role = inject(AuthService).userRole();
    if (role && allowedRoles.includes(role)) return true;
    inject(Router).navigate(['/login']);
    return false;
  };
};
✓ Las rutas siempre aplican ambos guards en cadena: canActivate: [authGuard, roleGuard([...])]. El authGuard se evalúa primero.

7. Interceptores HTTP

authInterceptor

Clona cada petición saliente y adjunta el header Authorization: Bearer <token> si existe un token en sesión.

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).getToken();
  if (token) {
    const cloned = req.clone({ setHeaders: { Authorization: `Bearer ${token}` } });
    return next(cloned);
  }
  return next(req);
};

errorInterceptor

Captura errores HTTP globalmente y ejecuta acciones según el código de estado:

CódigoAcción
401Limpia localStorage y redirige a /login (excepto si la petición era el propio login)
403Solo loguea una advertencia; cada componente maneja su propio 403
429Loguea advertencia de rate limit
500Loguea error interno del servidor

9. Servicios

AuthService

Servicio central de sesión. Gestiona el ciclo completo de autenticación con Angular Signals.

  • Signals reactivos: user(), userRole(), isAuthenticated()
  • Persistencia: Token y perfil guardados en localStorage
  • Restauración de sesión: Al arrancar, valida el token almacenado y recarga el perfil
  • Inactividad automática: Cierra sesión tras 30 minutos sin actividad del usuario
  • Decodificación JWT: Usa jwt-decode para extraer user_id y exp
  • Redirección post-login: Redirige automáticamente según el rol del usuario

11. Componentes — Módulo Auth

LoginComponent

  • Formulario con FormsModule (two-way binding).
  • Ejecuta reCAPTCHA v3 antes de enviar credenciales.
  • Llama a AuthService.login() → AuthService.fetchCurrentUser().
  • Redirige automáticamente según el rol: ADMIN→/admin, MESERO→/mesero, COCINA→/cocina.
  • Usa signals (loading, errorMessage) para el estado del formulario.
  • Previene doble envío verificando loading() al inicio.

RequestResetComponent / ResetPasswordComponent

  • Flujo de dos pasos para recuperación de contraseña.
  • Envía email para solicitar token → confirma con token + nueva contraseña.

12. Componentes — Módulo Admin

DashboardComponent

Vista de bienvenida con links de navegación a todos los módulos. Inyecta AuthService para mostrar datos del usuario y gestionar el logout.

UsuarioListComponent / UsuarioFormComponent

  • CRUD completo de usuarios del sistema.
  • El formulario detecta si es creación o edición según la presencia del parámetro :id en la ruta.
  • Permite activar/desactivar cuentas y asignar roles.

ProductoListComponent / ProductoFormComponent

  • Gestión del catálogo de productos.
  • El campo disponible controla si el producto aparece al crear pedidos.

MesaListComponent / MesaFormComponent

  • Gestión de mesas del restaurante.
  • Solo permite crear mesas; el estado es gestionado por el backend al crear/cerrar pedidos.

PagoListComponent

  • Lista de solo lectura de pagos registrados.
  • Usa PagoService.filtrarPorFecha() para filtrado por rango de fechas.

13. Componentes — Módulo Mesero

MesasViewComponent

  • Carga todas las mesas con MesaService.getAll().
  • Al hacer clic en una mesa libre navega a /mesero/pedidos/nuevo?mesa=:id.
  • Usa signal mesas para renderizado reactivo.

PedidoCreateComponent

  • Carga mesas libres (getDisponibles()) y productos disponibles al iniciar.
  • Implementa un carrito local con signal carrito de tipo ItemCarrito[].
  • Computed signal productosFiltrados para búsqueda en tiempo real por nombre.
  • Computed signal totalEstimado() para mostrar el total acumulado.
  • Al confirmar, llama a PedidoService.create() con el array de ítems.

PedidoListComponent

  • Computed signal pedidosOrdenados: los ABIERTOS primero, luego los CERRADOS, ambos grupos por fecha descendente.
  • Paginación de 10 elementos por página con computed signals.
  • Búsqueda por ID con PedidoService.getById().

PedidoDetailComponent

Componente más complejo del módulo mesero. Gestiona el ciclo completo de un pedido:

  • Signals: pedido, message, mostrarModal, productos, itemsNuevos, mostrarModalEditar, detalleEditando, cantidadEditar
  • Modal para agregar productos: carga ProductoService.getAll() solo la primera vez (lazy)
  • Modal para editar cantidad: llama a PedidoService.updateItems()
  • Eliminar ítem: llama a DetallePedidoService.delete()
  • Finalizar pedido: encadena cerrar() → registrarPago() con SweetAlert2 de confirmación
  • Eliminar pedido: SweetAlert2 de confirmación → PedidoService.delete() → navega a /mesero/pedidos

14. Componentes — Módulo Cocina

ProduccionComponent

  • Carga todos los detalles de pedidos con DetallePedidoService.getAll().
  • Signal filtroPedidoId + computed detallesFiltrados para filtrar por ID de pedido.
  • Método cambiarEstado(id, nuevoEstado) llama a DetallePedidoService.updateEstado() y recarga la lista.
  • No tiene acceso a crear, cerrar ni eliminar pedidos.

15. Seguridad

Autenticación JWT

  • El token se almacena en localStorage bajo la clave access_token.
  • En cada petición HTTP se adjunta automáticamente vía authInterceptor.
  • La expiración del token se valida decodificando el campo exp del JWT.
  • Al detectar un 401, el errorInterceptor limpia el storage y redirige al login.

Protección de rutas

  • Doble capa: authGuard (sesión activa) + roleGuard (rol autorizado).
  • Cualquier ruta no encontrada redirige a /login.

reCAPTCHA v3

  • El script de Google reCAPTCHA se carga dinámicamente en el cliente.
  • Se ejecuta con acción 'login' antes de enviar las credenciales.
  • El token generado se incluye en el body de POST /auth/login para validación en backend.

Cierre por inactividad

  • El AuthService escucha eventos mousemove, keydown, click y touchstart.
  • Tras 30 minutos sin actividad, ejecuta logout() automáticamente.
  • Solo se activa en el navegador (no en SSR).
⚠ El localStorage no es accesible en SSR. Todos los accesos están protegidos con la verificación typeof localStorage !== 'undefined' o con isPlatformBrowser().
